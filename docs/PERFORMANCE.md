# 资源占用与打包对照

2026-11-17，在同一台 Windows 11 x64、16 逻辑处理器电脑上采样。所有数值是短时样本，不是长期上限，也不代表每台电脑都相同。

## 正在运行的旧版

测试电脑上的 v1.0.1 已连续运行约两天。30.2 秒后台采样：

| 指标 | 观察结果 |
| --- | --- |
| 全机平均 CPU | 采样精度内为 0.0000% |
| 工作集 | 196.2–196.3 MiB |
| 私有内存 | 80.0–80.1 MiB |
| 进程句柄 | 954，采样期间稳定 |

工作集包括当前驻留的运行时和系统模块；私有内存另列。不能把旧进程与刚启动的新进程直接相减，归因于优化收益。

## 相同代码的打包对照

使用本次优化代码的 `UI_QA` 构建，两个模拟设备、固定一个托盘图标、窗口隐藏、每 30 秒更新。自包含 Windows x64 单文件，两次发布只改变 `EnableCompressionInSingleFile`；每次启动后预热 5 秒，再采样 30.1 秒。测试不与真实鼠标通信，不修改用户设置或自启动项。

| 指标 | 开启内部压缩 | 关闭内部压缩 |
| --- | --- | --- |
| 工作集 | 127.4–127.6 MiB | 61.9–62.1 MiB |
| 私有内存 | 53.5–53.7 MiB | 14.3–14.4 MiB |
| 全机平均 CPU | 0.0000% | 0.0065% |
| 句柄范围 | 434–445 | 434–445 |
| EXE 文件 | 49.3 MiB | 110.9 MiB |
| 仅主程序的 ZIP | 44.1 MiB | 45.3 MiB |

这组对照显示关闭内部压缩明显降低了该场景的内存占用，代价是解压后的 EXE 增大。CPU 数值很小、采样时间有限，不能据此判断两种打包方式的 CPU 优劣。正式发行包还包含说明和许可证，体积会略有不同。

微软说明，启用单文件内部压缩时，程序集会在启动时解压到内存：[.NET 单文件部署文档](https://learn.microsoft.com/en-us/dotnet/core/deploying/single-file/overview#compress-assemblies-in-single-file-apps)。发行脚本现已关闭这一层压缩，ZIP 保留压缩，用户仍无需另外安装 .NET。

另已移除每 300 毫秒检查第二实例请求的定时器，改为事件唤醒；隐藏窗口和菜单不重复同步设置，任务栏主题只在需要时重读。这些改动减少后台唤醒和临时分配。没有使用定时强制 GC 或清空工作集来降低显示数值。

当前已通过 101 项离线检查、11 项模拟托盘集成检查和第二实例唤醒检查。真实鼠标查询、长时间运行、休眠恢复和多设备组合仍需实机测量，不能用上述模拟替代。
