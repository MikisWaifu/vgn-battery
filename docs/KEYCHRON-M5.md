# Keychron 鼠标适配记录

v1.0.1 的枚举阶段只保留厂商编号 `3554`、`373B`、`391D`，因此 Keychron 的 `3434` 设备不会被发现。此时界面显示默认的“鼠标电量”和“未发现受支持的 USB 鼠标”，尚未进入电量查询。

v1.1.0 纳入 [MikisWaifu 的适配贡献](https://github.com/zerobeyondlogic/vgn-battery/pull/1)。下述实机接口、应答与耗时来自贡献者的 2026-11-15 记录；维护者目前没有 Keychron 设备复测。

## 设备与接口拓扑

贡献者于 2026-11-15 在 Windows 11 x64 上检查 `3434:D028`（Keychron Ultra-Link 8K 接收器，产品字符串 `Keychron Ultra-Link 8K`）。该复合设备提供 7 个 HID 集合：

| Usage Page / Usage | 输入 | 输出 | 用途 |
| --- | --- | --- | --- |
| `0001:0002` | 8 | 0 | 鼠标 |
| `0001:0006` | 21 | 0 | 键盘 |
| `0001:0006` | 8 | 2 | 键盘 LED |
| `000C:0001` | 3 | 0 | 多媒体键 |
| `008C:0001` | 33 | 33 | 未使用 |
| `FF60:0061` | 33 | 33 | QMK/VIA raw HID |
| `FFC1:0001` | 64 | 64 | 电量与状态通道 |

电量只在 `FFC1:0001` 上应答。`FF60:0061` 是 QMK 的 raw HID 通道，向它写 `B3 06` 会被当作另一套命令解析，因此接口筛选必须同时匹配 Usage Page、Usage 和输入/输出长度，不能只按厂商编号筛选。

接收器与鼠标本体使用不同编号：`3434:D028` 是接收器，任何鼠标经它配对后都以该编号出现；`3434:D048` 是 M5 的有线编号，`3434:D049` 是 M6 8K 的有线编号。

## 电量协议

依据开源内核模块 [keychron-battery-dkms](https://github.com/csutcliff/keychron-battery-dkms)（`keychron_battery.c`，常量 `KEYCHRON_REPORT_ID_CMD 0xB3`、`KEYCHRON_CMD_STATUS 0x06`、`KEYCHRON_BATTERY_OFFSET 20`、绑定接口 4），由贡献者在其电脑以只读查询复现。本项目仅参考协议事实，未复制或打包该内核模块的源码。

请求为 64 字节输出报告，报告 ID `B3`，命令 `06`，其余为零：

```text
B3 06 00 00 00 00 00 00 00 00 ... 00
```

应答为 64 字节输入报告，报告 ID `B4`，字节 `[1]` 回显命令，字节 `[20]` 为状态：bit 7 是充电标志，bit 6–0 是百分比：

```text
B4 06 00 00 00 00 20 03 20 03 20 03 20 03 20 03 1D 01 04 0A 64 00 ...
                                                            ^^ byte 20 = 0x64 = 100%
```

该协议没有校验和；有效性由报告 ID、命令回显和百分比范围（≤ 100）判定，与 17 字节 VGN 协议的 `sum % 256 == 55h` 不同。充电标志在 100% 时不足以证明仍在充电，界面沿用“已充满”的保守标签。

## 型号查询

接收器对任何配对鼠标都报同一 USB 编号，产品字符串也只有 `Keychron Ultra-Link 8K`。型号来自接收器自身的配对查询：报告 ID `B5`，命令 `03`。贡献者记录的 21 字节请求可获得应答（其测试中 64 字节同样被接受）；程序沿用 21 字节请求。

应答从 offset 3 开始，每 5 字节一个槽位，最多 3 个槽位，依次是 VID（小端）、PID（小端）、连接标志：

```text
B6 03 01 | 34 34 48 D0 01
            ^^ ^^ ^^ ^^ ^^
            VID 3434, PID D048, connected
```

上面的实测应答对应 Keychron M5。未登记的配对编号回退为接收器名称。v1.1.0 按接收器的独立设备标识缓存型号，避免多只接收器共用型号；缓存有效期为 60 秒，到期后在下次读取时重新查询。设备变更或查询失败会使缓存失效，随后重新识别。

## 安全边界与验证

程序只发送上述两条只读查询：电量状态，以及接收器的配对列表。不发送 DPI、回报率、配对、灯光或固件命令，也不访问 `FF60:0061`。

贡献者实测：`3434:D028` 接收器 + Keychron M5，读到真实 100%，连续 5 次查询在 2–40 ms 内返回，型号解析为 `Keychron M5`。维护者尚未复测；M5 的有线 `3434:D048`、M6 8K 的 `3434:D049`、休眠后的重试、多接收器组合以及长时间轮询对续航的影响仍待实机验证。协议解析和设备状态的离线检查不能替代这些测试。

若仍读不到，请右键选择“导出设备信息”，附上该 JSON。报告只包含描述符元数据，不含设备路径和序列号，也不向设备发送报告。
